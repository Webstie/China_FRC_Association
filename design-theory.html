从 0 到整机的设计框架

FRC 机器人设计不是从“我想画一个机构”开始，而是从比赛策略开始，逐层转化为功能、接口、尺寸、子系统和 CAD。好的理论框架能让全队在同一张地图上工作。

1

Game Strategy

分析规则、得分周期、防守压力和队伍能力，决定机器人要赢靠什么。

产物：优先级列表、必须做/可以放弃清单。
2

Robot Requirements

把战略翻译成可验证需求，例如“3 秒内完成拾取”“能达到 X 高度”。

产物：速度、范围、尺寸、重量、可靠性要求。
3

System Architecture

决定底盘、拾取、输送、得分、爬升、电控、线缆和维护空间如何共存。

产物：子系统边界、接口、空间分配。
4

Top-Down CAD

先建立整机 layout sketch 和关键基准，再让子系统从共同骨架派生。

产物：master sketch、关键平面、接口尺寸。
5

Subsystem Design

每个子系统根据接口做详细 CAD、传动计算、结构强度和可制造性检查。

产物：子系统 CAD、BOM、加工图。
6

Prototype & Freeze

先验证高风险物理问题，再冻结接口，进入制造、装配和迭代。

产物：测试结论、冻结版本、改版记录。

核心思想

Top-Down Design 不是先让每个人各画一个机构再拼起来，而是先在整机层面定义共同基准：机器人外框、轮子位置、game piece 路径、得分位置、关键轴线、电控空间和维护通道。

子系统设计必须引用这些共同基准。这样 intake、indexer、shooter、arm、电控和底盘不会互相打架，改动也能从 master layout 向下传递。

Top-Down CAD 产物 Master Layout Sketch：整机轮廓、关键轴线、game piece 路径 Interface Planes：子系统安装面、板件基准、孔位基准 Envelope Volumes：每个子系统允许占用的空间盒 Reference Geometry：高度、角度、中心距、机构行程

落地案例：从任务到整机 Layout

下面用一个通用 FRC 场景演示设计如何从 0 推进。它不是某一年规则的固定答案，而是一套可以迁移到任何赛季的思考方法。

案例任务：地面拾取 → 内部输送 → 高位得分

目标是在比赛中稳定完成一个常见得分循环：机器人从地面拾取 game piece，内部定位后送入得分机构，并在指定高度/距离完成得分。

Step 1

把战略变成需求

  • 循环时间目标：从接触 game piece 到得分完成不超过 6 秒。
  • 拾取要求：允许驾驶员有 10-15 cm 对位误差。
  • 得分要求：机构能覆盖目标高度，并允许小范围距离误差。
  • 可靠性要求：连续 10 次拾取不得卡料超过 1 次。
Step 2

画 Game Piece Flow

  • 入口：bumper 外侧或上方，确定 game piece 第一次接触的位置。
  • 定位：进入机器人后必须有硬基准或滚轮基准，不能在内部随机漂移。
  • 转交：intake 到 indexer、indexer 到 scorer 的交接点要提前定义。
  • 退出：得分机构出口方向、角度和防卡料空间要在 layout 里画出来。
Step 3

建立 Master Layout

  • 先画 frame perimeter、bumper zone、轮子和地面线。
  • 再画 game piece 外形和运动路径，而不是先画机构零件。
  • 标出关键轴线：拾取滚轮、输送滚轮、pivot、shooter wheel 或 elevator rail。
  • 用空间盒限制每个子系统，防止它们互相占空间。
Step 4

冻结接口再细化

  • 底盘给 intake 提供安装孔和前部空间。
  • indexer 必须接住 intake 输出的 game piece，而不是重新发明入口。
  • scorer 的入口位置由 indexer 出口决定，不能独立漂移。
  • 电控、电池和线缆路径要在接口冻结前确认。

整机架构要先回答的问题

Game Piece Flow

game piece 从哪里进入、如何定位、如何传到得分机构、卡住时怎么取出？这是整机最重要的路径。

Scoring Geometry

得分点的高度、距离、角度和容差是多少？机器人需要靠机械精度、视觉还是驾驶员对位？

Packaging

电池、主断路器、电控板、气动、线缆、维护工具和手的空间是否提前留出？

Interfaces

子系统之间通过哪些孔、轴、板、平面和电气接口连接？接口必须比机构细节更早冻结。

Manufacturing Plan

队伍实际能做什么：手钻、3D 打印、激光切割、CNC、外包？设计必须匹配加工能力。

Serviceability

比赛现场能否 5 分钟换轮子、换皮带、换电机、检查线缆？维护性不是最后再补的。

可直接使用的落地模板

Robot Requirements 模板

  • 这个功能服务哪个得分策略？
  • 目标循环时间是多少？
  • 需要覆盖哪些高度、距离、角度或位置？
  • 允许多少驾驶误差？
  • 失败时是否会让整机无法继续比赛？

Subsystem Interface 模板

  • 输入来自哪个子系统？输出给哪个子系统？
  • 安装面、孔位、轴线和空间盒是否明确？
  • game piece 交接点的高度、角度和速度是多少？
  • 线缆、气管、传感器和维修工具从哪里进入？
  • 接口改动需要通知哪些小组？

Prototype Test 模板

  • 这次原型要验证什么风险？
  • 成功标准是什么？例如 10 次成功 8 次。
  • 需要记录哪些数据？速度、电流、命中率、卡料次数。
  • 测试失败后是改参数、改结构，还是放弃方案？
  • 测试结论是否已经写回 CAD 和设计表？

Design Freeze 模板

  • 冻结哪些接口：frame、孔位、轴线、外形空间、电控位置？
  • 哪些内容允许继续改：板件减重、滚轮材料、护板、传感器支架？
  • 每个改动是否有负责人、截止时间和回退方案？
  • 加工文件是否和冻结 CAD 版本一致？
  • 装配顺序和维修策略是否已经确认？

从理论到 CAD 的工作流

阶段 团队要做什么 必须留下的产物
Kickoff 后 24 小时 读规则、列得分动作、估算循环时间、决定战略优先级。 Strategy Matrix / Must-Should-Could 清单
概念设计 画 game piece flow、整机空间盒、关键动作草图。 Robot Layout Sketch / 子系统接口草图
原型验证 验证抓取稳定性、发射轨迹、升降行程、卡料风险等高风险问题。 测试视频、数据、通过/失败结论
详细 CAD 根据 master layout 做子系统 CAD、传动计算、BOM 和加工图。 CAD 版本、BOM、加工文件、装配顺序
设计冻结 冻结接口和关键尺寸，只允许受控改动。 Design Freeze 版本、变更记录

设计评审清单

  • 这个设计是否直接服务于队伍的比赛战略？有没有做了很酷但收益不高的功能？
  • 每个需求是否可验证：速度、重量、高度、行程、循环时间、可靠性？
  • 是否已经画出 game piece 从进入到得分的完整路径？
  • 子系统接口是否明确：安装孔、轴线、板面、空间盒、电气和维护通道？
  • Master layout 是否驱动了子系统，而不是各子系统各画各的？
  • 关键传动是否计算过速度、扭矩、电流、中心距和张紧方式？
  • 电池、电控、主断路器、线缆和维修空间是否在整机早期就安排好？
  • 最容易失败的物理问题是否已经用原型验证，而不是只在 CAD 里假设可行？
