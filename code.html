Intro to Code

从 WPILib 环境搭建到 Command-Based 机器人代码，用一条清晰路线帮助中国 FRC 队伍完成第一次可靠部署。

开始学习 必备工具 
package frc.robot;

public class RobotContainer {
  private final DriveSubsystem drive = new DriveSubsystem();
  private final CommandXboxController driver =
      new CommandXboxController(0);

  public RobotContainer() {
    drive.setDefaultCommand(
      new RunCommand(() -> drive.arcadeDrive(
        -driver.getLeftY(),
        -driver.getRightX()
      ), drive)
    );
  }
}
RIO 已连接 已启用

编程入门

FRC 机器人通常使用 WPILib 编程。它是由 WPI 和 FIRST 社区维护的机器人编程库，支持 Java、C++ 和 Python，并包含项目模板、仿真工具、底盘辅助库和部署命令。

对新队伍来说，建议从 Java 开始。它的官方文档最完整、示例最多，也最容易在比赛季找到社区答案。

推荐语言 Java
核心框架 Command-Based
第一目标 驾驶 + 部署

Part 0 · 先看清整个系统

机器人代码到底跑在哪

你写的代码是一段 Java 程序，但它不是跑在你的电脑上，而是跑在机器人上一台叫 roboRIO 的实时控制器上。电脑只用来写代码和上传代码；比赛时电脑跑 Driver Station，把手柄输入和 enable 信号通过 Wi-Fi 转给 roboRIO。 

        你的电脑 / Your laptop
   ┌─────────────────────────────────┐
   │  VS Code        — 写 & 部署代码    │
   │  Driver Station — 驾驶机器人         │
   └────────────────┬────────────────┘
                    │  Wi-Fi / USB（比赛时仅 Wi-Fi）
                    ▼
            ┌───────────────┐
            │  Robot Radio  │
            └───────┬───────┘
                    │  Ethernet
                    ▼
        ╔═══════════════════════════╗
        ║  roboRIO                  ║
        ║   · 跑你的 Java 代码         ║
        ║   · 50 Hz 控制循环           ║
        ║   · 与所有硬件通信            ║
        ╚════╤═════════════════╤══════╝
       CAN   │                 │  DIO / PWM / Ethernet
             ▼                 ▼
   ┌──────────────────┐  ┌───────────────────────┐
   │ 电机控制器         │  │ 传感器 / 气动 / 协处理器  │
   │ TalonFX · Kraken │  │ 限位 · 光电 · Limelight │
   │ SparkMax · Flex  │  │ PhotonVision           │
   └────────┬─────────┘  └───────────────────────┘
            │ 3-phase
            ▼
       ┌─────────┐
       │  电机    │
       └─────────┘

按"职责链"来读：你的代码 → roboRIO → CAN / 线 → 电机控制器 → 电机；手柄输入反向流动：摇杆 → Driver Station → 电台 → roboRIO → 你的代码。你的代码是把"人的输入"和"电机输出"连起来的唯一一层 —— 这就是全部工作。

只跑一次 启动 (boot)

创建对象、配置电机、写 CAN ID。凡是"建立世界"的代码都放这里。

永远在跑，50 Hz 20 毫秒节拍

读传感器 → 跑逻辑 → 写电机输出 → 等下一拍。必须远低于 20 毫秒，否则机器人会卡。

写任何新函数的第一个问题 这是 boot 阶段的一次性配置，还是每一拍都要跑的工作？每一行机器人代码都属于这两个时钟之一。

学习路线

从零到一台可用的机器人

一条连续的路线：每一步都建立在上一步的成果上。走完之后，你的代码能开底盘、能用按键控制一个机构、能在 auto 开始时前进 —— 这就叫"可用"。请按顺序来。

  1. 00

    先看清整个系统

    先读上面的系统说明：代码跑在哪、从 Driver Station 到电机的链路，以及两个时钟：启动一次、每 20 毫秒一拍。

  2. 01

    配置你的电脑

    按正确顺序装好工具链，再把模板项目编译、部署，直到 Robot Code 变绿。

  3. 02

    第一次让机器人动

    一颗电机、一个按键。最小可追踪的信号链路，先用裸 TimedRobot。

  4. 03

    让底盘开起来

    在 KOP 差速底盘上实现 arcade drive —— 顺便看隐性假设怎么悄悄堆积。

  5. 04

    为什么需要框架

    加第二个机构的那一刻，单文件写法就开始腐烂。于是有了 Command-Based。

  6. 05

    用 Command-Based 重写

    四个核心部件 —— Subsystem、Command、Trigger、Scheduler —— 叠在 TimedRobot 之上。

    动手实战：一颗电机、一个按键 →

  7. 06

    加一个机构

    A 键控 intake，用你以后每个 subsystem 都会重复的那套模式。

  8. 07

    第一段自动

    先定时前进、加 auto chooser，再用 PathPlanner / Choreo 画真正的路径。

    PathPlanner → Choreo →

  9. 08

    稳定迭代

    edit-build-deploy-test 循环、读懂 Driver Station 的灯，从第一天就用 Git。

  10. 09

    伙伴工具

    Driver Station、Phoenix Tuner X、REV Hardware Client、各种仪表盘 —— 整个赛季都开着的应用。

    Dashboards 仪表盘 → Driver Station →

    新手之后
