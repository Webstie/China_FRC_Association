目标

在 KOP 底盘上跑 arcade drive

KOP 风格的差速底盘左右各一到两颗电机。驾驶模型很简单：左摇杆控前进、右摇杆控转向。这就是 arcade drive。

上一页你让一颗电机转了起来。这一页你会接好四颗电机，喂给它一个 Xbox controller，真正把机器人在地上开起来。做完机器人能动了 —— 但你走到这一步的方式，悄悄塞进了一堆假设，而这正好引出下一页。

左摇杆 Y 前进速度
右摇杆 X 转向速率

把数学画出来

arcade drive 背后的数学

两个摇杆给出两个数 —— 前进速度和转向速率 —— arcade drive 把它们混合成左、右两路电机指令。向前推，两边都变正；再加转向，一边加速、另一边减速。每个结果在送进电机之前都被夹到 [-1, +1] 区间。 

        ┌──────────────────────────────────────────┐
        │   left stick Y      = forward speed      │
        │       (push up = +1, pull down = -1)     │
        │                                          │
        │   right stick X     = turn rate          │
        │       (right = +1, left = -1)            │
        └──────────────────────────────────────────┘
                              │
                              ▼
              ┌──────────────────────────────┐
              │   left motor  = Y + X        │
              │   right motor = Y - X        │
              └──────────────────────────────┘
                              │
                              ▼
                   clamp each to  [-1, +1]
                          │
                          ▼
                  leftMotor.set(left)
                  rightMotor.set(right)
  • 向前推 → 两边都正 → 前进。
  • 前进 + 右转 → 左边快、右边慢 → 向右画弧。
  • 单独右转 → 左正右负 → 原地右转。

你不用自己算这套数学。WPILib 自带的 DifferentialDrive 全帮你做了 —— 混合和夹值都包含在内。把数学画出来，是为了让你信任这个工具，而不是把它当黑魔法。

代码

代码 —— 最后一次用 TimedRobot

四颗 SparkMax 电机控制器：左边两颗、右边两颗。每一侧一个 leader 一个 follower；follower 只是跟随它的 leader，启动期配一次即可。DifferentialDrive 接收两个 leader，负责 arcade 数学。在 teleopPeriodic 里读摇杆、交给它 —— 整个驾驶循环就这么多。

注意摇杆前的负号：Xbox controller 向上推时 Y 是负值，所以取反才让前进为正。这是最后一页使用裸 TimedRobot —— 从下一个机构开始，我们就切到框架。 

// src/main/java/frc/robot/Robot.java
package frc.robot;

import com.revrobotics.spark.SparkMax;
import com.revrobotics.spark.SparkLowLevel.MotorType;
import edu.wpi.first.wpilibj.TimedRobot;
import edu.wpi.first.wpilibj.XboxController;
import edu.wpi.first.wpilibj.drive.DifferentialDrive;

public class Robot extends TimedRobot {

    private final SparkMax leftLeader  = new SparkMax(1, MotorType.kBrushless);
    private final SparkMax leftFollow  = new SparkMax(2, MotorType.kBrushless);
    private final SparkMax rightLeader = new SparkMax(3, MotorType.kBrushless);
    private final SparkMax rightFollow = new SparkMax(4, MotorType.kBrushless);

    private final DifferentialDrive drive =
        new DifferentialDrive(leftLeader, rightLeader);

    private final XboxController driver = new XboxController(0);

    public Robot() {
        // followers mirror their leader — set this once at boot.
        // 跟随者跟随主电机，启动期配一次即可。
        leftFollow .configure(/* follow leftLeader  */);
        rightFollow.configure(/* follow rightLeader */);
    }

    @Override
    public void teleopPeriodic() {
        drive.arcadeDrive(
            -driver.getLeftY(),   // Xbox up = negative; invert for forward
                                   // Xbox 向上是负值，取反才前进
            -driver.getRightX()
        );
    }
}

悄悄堆积的隐性假设

代码里悄悄长出的隐性假设

这能跑。你现在能开车了。但仔细看 —— 一堆没说出口的假设已经悄悄爬进了这一个文件。在只有一个机构时它们都不痛不痒。加第二个机构的瞬间，裂缝就出来了。

  1. 01

    CAN ID 是内联的魔数

    ID 1、2、3、4 直接写在创建电机的地方 —— 散落在文件里。换一个控制器，你就得一行一行去找。没有一个地方统一写着"这些是 ID"。

  2. 02

    默认值塞在一个方法里

    摇杆端口 0、没死区（deadband 0）、没斜率限制（slew limiting）—— 所有的输入行为都埋在一句 arcadeDrive 调用里。想调驾驶手感，只能去改循环体本身，没有别的地方。

  3. 03

    一切都挤在一个文件里

    驱动逻辑、输入读取、电机接线全缠在 Robot.java 里。一个机构这样写没问题。但在 A 键上加一个 intake —— 按住吸、松开停 —— teleopPeriodic 里就开始把驾驶和 intake 混在同一个循环里，抢同一块地方。

这就是悬崖边。裸 TimedRobot 里放一个机构还能读；两个就开始缠在一起；四个就没法维护了。下一页会故意从这个边缘直接走下去 —— 用最朴素的方式硬加一个 intake —— 让你在拿到框架之前，先亲身感受到为什么需要它。

底盘类型速览

底盘类型有哪几种

你刚开的这台底盘，是 FRC 里你会遇到的三大类之一。每一类都是一种工具，有不同的成本和复杂度权衡。你现在不必全部精通 —— 只要知道自己机器人上是哪一种，以及另外两种大致换来什么。

左右两侧 · 齿轮传动 Differential（差速 / Tank）

KOP 经典款，也叫 "west coast"。左右两侧、每侧一到两颗带齿轮的电机；靠两侧不同速度来转向。DifferentialDrive 开箱就给你 arcade、tank、curvature 三种驾驶模式。便宜、简单、皮实 —— 预算紧、训练、第一台机器人的正确选择。

DifferentialDrive
能横向平移 Mecanum

四个带斜向滚子的 mecanum 轮，让机器人能横向平移、原地旋转 —— 不用 swerve 那套复杂度就能实现全向运动。MecanumDrive 负责混合数学。它如今基本失宠了，因为很容易被推动（pushability 差）：那些滚子牺牲了大量抓地力。

MecanumDrive
每个轮独立转向 + 驱动 Swerve

每个轮都有自己的 drive motor 和 steer motor，所以机器人可以朝任意方向移动、同时朝向任意方向。正因为这种灵活性，它统治了 2024 年以后的比赛。代价是成本和复杂度：CTRE swerve API、YAGSL、MAXSwerve 这些 vendor stack 存在的意义就是驯服它。完整内容后面会单独成页。

常见的坑

常见的坑

几乎每一台第一次的差速底盘，都会以这三种方式之一出问题。它们看起来像"机器人坏了"，但只要知道该查什么，每一个都是一行就能改好的。

  1. 01

    某一侧的反向设反了

    差速底盘的两侧朝向相反，所以必须把一侧反向（invert）。设反了，向前推机器人就会画弧 —— 甚至原地打转 —— 而不是直走。症状："前进"变成了转圈。

  2. 02

    齿轮比常数填错

    齿轮比（gear ratio）把电机转数换算成轮子转数。常数填错，所有距离和速度计算都会差这个倍数 —— 机器人"以为"自己开了一米，实际只开了半米。编码器读数本身没问题，问题出在它之上的数学。

  3. 03

    轮半径单位混用

    在同一个计算里悄悄混用英寸和米，是经典翻车点。WPILib 的 odometry 和 kinematics 都用米；轮半径留成英寸，会让每个 pose 和 trajectory 偏差 39.37 倍。统一一个单位（米），并贯彻到底。
