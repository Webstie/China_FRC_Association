工具地图

五类工具，每类只做一件事

到目前为止，主线一直是你写的代码。但整个赛季还有几款伙伴应用会一直开着，它们各自只做一件事，跟你的代码并行配合。新手最容易把"装个工具"和"会用工具"混为一谈 —— 这里给你一张工具地图。

其中两类（trajectory authoring、characterization）要等到你开始上 closed-loop 和路径跟随后才用得到 —— 见"新手之后"。剩下三类（驾驶舱、设备配置、仪表盘）从 Week 1 就要用。

驾驶舱 Driver Station
设备配置 Tuner X · REV HC
仪表盘 Elastic · AdvantageScope
共用传输 NetworkTables 4

五个类别

五类工具一览

你的机器人代码处在正中间。每一类工具都通过一条明确的通道和它相连 —— enable 信号、CAN 配置、NetworkTables、轨迹文件，或日志分析。知道某个工具占的是哪条通道，就知道什么时候该开它。

1 · 驾驶舱 Driver Station

比赛时驾驶和操作手唯一会看的程序：enable、disable、模式选择、手柄，以及打印 stack trace 的控制台。通过 enable / disable / FMS 和机器人相连。

enable / disable / FMS
2 · 设备配置 Phoenix Tuner X · REV Hardware Client

Phoenix Tuner X 管 CTRE 设备（TalonFX、Kraken、CANcoder、Pigeon 2）；REV Hardware Client 管 REV 设备（SPARK MAX、SPARK Flex、PDH、PH）。两者都做 CAN config 和固件 —— 代码自己做不了的事。

CAN config + 固件
3 · 仪表盘 SmartDashboard · Shuffleboard · Elastic · AdvantageScope

笔记本上的窗口，显示你的代码发布出来的内容。它们共用同一个传输 —— NetworkTables 4。Elastic / Shuffleboard 给驾驶员看；AdvantageScope 是程序员的窗口，看实时数据和日志回放。

NetworkTables (NT4) + DataLog
4 · 轨迹作图 PathPlanner GUI · Choreo

在场地图上画或优化自动路径，再导出代码要跟随的文件。PathPlanner 输出 .path / .auto 文件，Choreo 输出 .traj 文件。开始做路径跟随后才用得到。

.path / .auto / .traj 文件
5 · 系统辨识 SysId

驱动机构跑一段已知流程，分析日志，给你 feedforward 增益（kS、kV、kA）。开始做 closed-loop 控制后才用得到。

测出 kS, kV, kA

设备配置

设备工具 — Tuner X 与 REV HC

两个设备工具几乎覆盖了 FRC 机器人上所有电机控制器和传感器。它们都在笔记本上跑、和 CAN 总线通信，做代码做不了的事：分配 CAN ID、刷固件、在还没有任何代码时先测电机。机械组问"为什么这个电机不转？"，答案几乎总是 CAN ID 写错了或固件没刷 —— 所以先开设备工具。

CTRE 设备 Phoenix Tuner X

CTRE 全套设备的统一配置工具：TalonFX（Falcon / Kraken）、Talon FXS、CANcoder、Pigeon 2、CANdi、CANrange、CANdle。四件事：(1) Discover & ID —— 列出总线上每个设备，给每个分配和代码对得上的唯一 CAN ID；(2) Firmware —— 升级到当年 Phoenix 6 固件，必须和 WPILib 年份对应；(3) Self-test + Plot —— 一次性把所有 status signal 抓下来，再实时画 setpoint vs 实测，FRC 里 PID 调参就是这么干的；(4) Swerve Project Generator —— 一个向导，直接帮你写出整个 CommandSwerveDrivetrain 和 generated/TunerConstants.java。生成的文件一行都不要手改，参数变了就重跑向导。

完整指南 →
REV 设备 REV Hardware Client

REV 对位的 Tuner X，管 SPARK MAX、SPARK Flex、PDH、PH、Servo Hub。四件事：(1) Discover & ID —— USB-C 直连每个 SPARK；(2) Firmware —— 刷 SPARK、PDH、PH 的固件；(3) Manual test —— 写任何代码之前用一个滑块转电机，把所有代码相关的变量排除掉；(4) One-time config，比如 follower 模式。与 Tuner X 的关键差异：REV 的配置写在代码里，不在 GUI 里 —— 标准做法是启动时调用 SparkMaxConfig + motor.configure(...)。GUI 只用于一次性操作（设 ID、刷固件）和手动测试。

出问题先开哪个工具

新手作弊条

出问题时最慢的做法是把所有工具乱开一遍。这张表把症状直接映射到那个握着答案的工具。打印出来，贴在笔记本电脑包里。

出什么问题 开这个工具
代码部署不上 Driver Station（Diagnostics 标签页 —— rio 到底连得上吗？）
部署了但 Robot Code 灯红了 Driver Station（Messages —— stack trace 就在里面）
TalonFX 或 CANcoder 没反应 Phoenix Tuner X（Devices —— ID？固件？在总线上吗？）
SparkMax 没反应 REV Hardware Client（Devices —— ID？固件？）
PID 不对（振荡、超调） Phoenix Tuner X Plot（CTRE 电机）或 AdvantageScope（任意传感器）
Auto 跑完位置不对 AdvantageScope（回放 DataLog —— 看实际 pose vs 目标 pose）
驾驶员说手感不对 AdvantageScope（Joysticks 标签页 —— 看清楚原始 axis 值到底是多少）
CAN 总线像超载 Driver Station（Power/CAN 标签页 —— 利用率 %、错误计数）

常见的坑

常见的坑

这些工具很少大声报错，下面这些坑都很安静 —— 能在赛场上白白浪费一下午，直到有人才注意到。

  1. 01

    把工具当成"装一下就完了"

    每个伙伴应用只做一件事。如果你全装了却没搞清每个占的是哪条通道 —— enable 信号、CAN config、NetworkTables、轨迹文件 —— 出问题时就会开错那个，白白浪费一下午。要记的是工具地图，不只是下载链接。

  2. 02

    没在 Driver Station 里把手柄绑死端口

    在 DS 的 USB Devices 标签页里把每个手柄绑死端口。否则比赛中拔过一次线，所有人的端口编号都会轮换 —— 你代码里读的还是 port 0，但现在坐在那个端口上的是另一个物理手柄，操作手按的键就变成驾驶员命令。

  3. 03

    固件和 WPILib 年份对不上

    Phoenix 6 固件必须和 WPILib 年份对应，REV 设备同理。一颗"不转"的电机，最常见的原因就是 CAN ID 写错或固件没刷 —— 动代码之前先开设备工具（Tuner X 或 REV HC）把这两样都查一遍。

  4. 04

    手动改生成的 TunerConstants.java

    Swerve Project Generator 帮你写出 generated/TunerConstants.java，里面装着每个模块 ID、传动比、增益、CANcoder offset。绝对不要手改 —— 参数变了就重跑向导。手改的内容下次有人重新生成时会被静默覆盖。

  5. 05

    不开 Plot，靠手感调 PID

    看不见的 PID = 没法调的 PID。新手不开 plot，靠手摸车身振动猜 —— 永远调不出来。开 Tuner X Plot（或 AdvantageScope），画 setpoint vs 实测，看着曲线调。

  6. 06

    以为 REV 的配置能从 GUI 里记住

    和 CTRE 设备不同（CTRE 能记住你从 Tuner X 推下去的设置），REV 的标准做法是启动时调用 SparkMaxConfig + motor.configure(...)。REV HC 的 GUI 只用于一次性操作（设 ID、刷固件）和手动测试 —— 真正的配置要放在代码里，否则一次断电就不会像你想的那样保留。
