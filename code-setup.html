是什么 & 为什么

按这个确切顺序安装

按这个确切顺序装。每一项都依赖它上面那一项 — 跳着装，后面某一步会悄悄挂掉，而且很难排查。这就是一个新手程序员开工前需要的整条工具链。

Game Tools 装的是 NI 运行库，WPILib 和 Phoenix Tuner X 都依赖里面的组件，所以它排第一。WPILib 自带 JDK — 不要自己装 Java，否则 Gradle wrapper 会挑错版本，啥都编译不了。vendor tool 只装你手上真有的那家电机控制器；KOP 队伍拿到手的通常是 REV。Git 严格说是可选的，但还是第一天就装上。

四件套

每件工具是干什么的

每件工具一句话，让你知道自己在装什么、为什么它在清单上。前两件人人必装；vendor tool 取决于你的硬件；Git 是能救你整个赛季的习惯。

必装 · 仅 Windows FRC Game Tools

打包了 Driver Station（开车、看报错）和 roboRIO Imaging Tool（给 rio 烧今年的镜像）。仅 Windows，没有 macOS / Linux 版。下载需要管理员权限和一个免费的 NI 账号。

详见：FRC Game Tools 页面
必装 · 全平台 WPILib VS Code

预配置好的 VS Code，带 WPILib 扩展、WPILib SDK 和一个锁定版本的 JDK。它同时是你的编辑器、build 工具（Gradle）和 deploy 按钮。自带的 JDK 是关键 — 永远不要单独装 Java。

详见：WPILib 页面
vendor · 二选一 Phoenix Tuner X / REV HC

给你的电机控制器做配置和刷固件的工具。CTRE 硬件（TalonFX、Kraken、CANcoder、Pigeon 2）用 Phoenix Tuner X；REV 硬件（SparkMax、SparkFlex、PDH、PH）用 REV Hardware Client。只装和机器人上硬件匹配的那一个。

Phoenix Tuner X · REV Hardware Client
推荐 · 第一天 Git

版本控制。Git for Windows 还附带 Git Bash。部署代码并不是非它不可，但当你第一次在比赛前夜把能跑的机器人改坏，一份干净的提交历史就是救命稻草。

证明它通了

验证安装 — 点亮那盏绿灯

没有把模板项目编译并部署成功之前，都不算装好。Day 1 就要做这一步，早于你自己写任何一行逻辑。Robot Code 绿灯亮起，是唯一能证明你整条工具链从头到尾都通的测试。

  1. 01

    新建一个模板项目

    在 VS Code 里：Ctrl+Shift+P → WPILib: Create New Project。选 Template · Java · TimedRobot Skeleton，填上队号，点 Generate。不要发挥，原样用模板。

  2. 02

    编译机器人代码

    Ctrl+Shift+P → WPILib: Build Robot Code。第一次 build 会下载 Gradle 和依赖，可能要几分钟 — 这是正常的。成功的标志是终端里出现 BUILD SUCCESSFUL 这行。

  3. 03

    如果 build 失败

    按顺序查三件事：JDK（是不是有人单独装了 Java？）、杀毒软件（是不是把 gradlew.bat 隔离了？）、网络（首次下载 Gradle 需要联网）。第一天的失败大多是这三个之一。

  4. 04

    连上 roboRIO 并部署

    用 USB 或电台连上一台 roboRIO。然后 Ctrl+Shift+P → WPILib: Deploy Robot Code。这一步会 build、上传到 rio，并启动你的程序。

  5. 05

    Robot Code 灯 → 绿

    打开 Driver Station，盯着 Robot Code 灯。绿色，说明你刚成功把第一个 build 部署到了机器人上。红色，说明有 exception — 打开 riolog 或 DS 控制台读它。那盏绿灯就是目标；写任何逻辑之前先点亮它。

硬件现实

电脑与系统现实

FRC 里唯一的硬约束：Driver Station 和 Game Tools 仅 Windows。你可以在 macOS 或 Linux 上写、build、deploy 代码，但没法跑 Driver Station 在比赛里真正 enable 机器人。每支队伍至少需要一台 Windows 笔记本。下面是每个平台能做和不能做的事，以及硬件下限。

需求 说明
Windows 阻力最小的路。什么都能跑：VS Code + Gradle、Driver Station、Game Tools、roboRIO 烧录、所有 vendor tool。唯一能跑比赛的系统。
macOS 能跑 VS Code + Gradle（写、build、deploy 代码）。跑不了 Driver Station、Game Tools、roboRIO 烧录。当开发机没问题，上场没用。
Linux 能跑代码，Game Tools 只有部分支持，无法用于 FRC 比赛。最多当个只写代码的开发机。
内存 / CPU 8 GB 内存能用；推荐 16 GB。Gradle build 和 VS Code 一起吃内存。
磁盘空间 为整条工具链外加一个赛季的 vendordep 和 Gradle 缓存，留出大约 20 GB 空闲空间。
管理员权限 运行 NI Game Tools 安装程序需要。如果是学校统管的笔记本，安装当天前先借好管理员账号。
USB 接口 比赛笔记本上至少留一个 USB-A 接口 — 偶尔要用它 USB 直连电台或 rio。纯 USB-C 的机器得带个转接头。

和 rio 对话

每个程序员都该懂的网络基础

你的代码跑在 roboRIO 上，你的笔记本得通过网络找到它。寻址 rio 有两种方式，连接也有两种方式。把这些理顺，“我 deploy 不上去”就不再是个谜。

rio 的静态 IP 是 10.TE.AM.2 的形式，由队号算出来：把队号拆成两半（TE 和 AM），各自补零到合适长度。Team 1234 → 10.12.34.2；team 88 → 10.0.88.2；team 9006 → 10.90.06.2。你也可以用它的 mDNS 主机名 roborio-####-frc.local 来访问，#### 是队号 — 只要网络不屏蔽 mDNS 就好用。

USB 直连模式最可靠 — 一根线直插 rio，中间没有 Wi-Fi，适合维修区和调试。无线模式经过机器人电台，是真正比赛用的，但家里或学校的 Wi-Fi 常屏蔽 mDNS，导致 .local 主机名失效。开发时拿不准，就用 USB 直连。 

team number  ──►  static IP        mDNS hostname
队号              静态 IP            mDNS 主机名
─────────────────────────────────────────────────
   1234     ──►  10.12.34.2        roborio-1234-frc.local
     88     ──►  10.0.88.2         roborio-88-frc.local
   9006     ──►  10.90.06.2        roborio-9006-frc.local

rule / 规则:  team = TE|AM  →  10.TE.AM.2  (right-pad each half)

connection / 连接方式
─────────────────────────────────────────────────
USB tether   most reliable, no Wi-Fi    pit + debugging
USB 直连      最可靠、不经 Wi-Fi          维修区 + 调试
Wireless     through robot radio        real matches
无线          经机器人电台                正式比赛 (mDNS 可能被屏蔽)

常见的坑

配置时最容易踩的坑

几乎所有第一天的安装问题都逃不出这四个。这些坑在安装界面里都看不出来，但踩过一次以后就再也不会上当。

  1. 01

    单独装 Java，破坏了 WPILib 的 JDK pin

    WPILib 自带一个锁定版本的 JDK。如果你单独装了 Java，Gradle wrapper 可能挑到错的那个，build 以莫名其妙的方式失败。卸掉多余的 Java，或让 WPILib 指向它自带的 JDK。

  2. 02

    在 macOS 上装 Game Tools 还指望它能用

    Game Tools 和 Driver Station 仅 Windows — 没有能跑比赛的 macOS 版。macOS 写代码、部署代码都行，但真正 enable 机器人需要一台 Windows 笔记本。

  3. 03

    用了一个屏蔽 mDNS 的 Wi-Fi 网络

    家里和学校的网络常屏蔽 mDNS，导致 roborio-####-frc.local 主机名失效，deploy 找不到 rio。改用 USB 直连，或用静态 IP 10.TE.AM.2 代替 .local 名字来访问 rio。

  4. 04

    杀毒软件把 gradlew.bat 隔离了

    有些杀毒软件会隔离 gradlew.bat 或拦截首次 Gradle 下载，build 失败却看不出原因。把项目文件夹加白名单，新项目编译不过时去查杀软的隔离记录。
