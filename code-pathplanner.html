是什么

PathPlanner 是什么

PathPlanner 是一个独立桌面应用（Windows / macOS / Linux），跟 VS Code 并排开着用。界面是一张场地图，上面有你的机器人图标。你拖航点 → 它在航点之间画顺滑样条 → 计算轨迹 → 把 .path 文件存到项目的 src/main/deploy/pathplanner/ 目录下。

它和两样东西配套：机器人代码里的 PathPlannerLib 库，以及把存盘文件接成可运行 Command 的 AutoBuilder API。它是 FRC 自动流程的新手默认选择：Week 1 的 auto 大约 20 分钟就能画好上场。

绘制方式 手画样条
文件存放 deploy/pathplanner/
配套库 PathPlannerLib
接入 API AutoBuilder

GUI 界面

GUI 界面长什么样

窗口就是当年的场地图，路径画在上面。每个圆点是你拖动的航点，点与点之间的曲线是 PathPlanner 算出的样条。点开任意航点可以编辑它的属性，整条路径还有全局约束可设。

  • 经过时的朝向 — 机器人经过该航点时朝向哪个方向。
  • 速度覆盖 — 在该航点强制指定速度，覆盖整条路径的默认速度。
  • 事件标记 — 一个带名字的标记，在代码里触发一条 Command（也就是你的 NamedCommand）。
  • 约束 — 最大速度、最大加速度，以及让机器人慢下来的区域 (zones)。

生成的文件

PathPlanner 生成的文件

你画的一切都会落成 src/main/deploy/pathplanner/ 下的文件，随代码一起部署到 roboRIO。一共三类：.path 是单条画出来的路线，.auto 把多条 path 和 command 拼成一整套流程，settings.json 存机器人的物理配置、每台车配一次。

文件 来自 代码里加载用
paths/MyPath.path 拖航点 PathPlannerPath.fromPathFile("MyPath")
autos/MyAuto.auto 在 GUI 里把多个 path 和 command 拼起来 new PathPlannerAuto("MyAuto")
settings.json 每台机器人一次 隐式读取

代码接入模式

代码接入模式 —— 只写一次

在 RobotContainer 构造函数里，你只在启动期写两段代码。AutoBuilder.configure 告诉 PathPlannerLib 怎么读和指挥你的底盘：怎么读 pose、auto 开始时怎么 reset pose、怎么读当前速度、怎么下发速度指令、路径跟随的 PID controller、从 GUI settings 来的 robotConfig、alliance 翻转规则，以及它 require 哪个 Subsystem。 

// In RobotContainer constructor — ONCE, at boot.
// 在 RobotContainer 构造函数里，启动期一次性配置。
AutoBuilder.configure(
    drive::getPose,                  // how to read pose
    drive::resetPose,                // how to reset pose at auto start
    drive::getChassisSpeeds,         // how to read current speeds
    drive::driveRobotRelative,       // how to command speeds
    new PPHolonomicDriveController(  // path-following PID
        new PIDConstants(5.0, 0, 0), // translation
        new PIDConstants(5.0, 0, 0)  // rotation
    ),
    robotConfig,                     // mass, MOI, modules — from GUI settings
    () -> DriverStation.getAlliance()
            .map(a -> a == Alliance.Red).orElse(false),
    drive                            // requires this Subsystem
);

// Named commands — what PathPlanner's "event markers" in the GUI map to.
// 命名命令 —— GUI 里事件标记对应的代码 Command。
NamedCommands.registerCommand("ShootNow", launcher.shootCommand());
NamedCommands.registerCommand("StartIntake", intake.intakeCommand());

有了这两段代码，pathplanner/autos/ 下任何 .auto 文件都能变成一个 Command。成熟队伍的 RobotContainer.java 第 91–380 行就是这个模式，只是 NamedCommand 多得多 —— 骨架完全一样。

GUI 到代码的流转

两半之间的交接就是文件和名字。GUI 把 .path/.auto 存进 deploy 目录，代码在启动时读它们。你在 GUI 里打的事件标记，按名字对应到你用 NamedCommands 注册的 Command。

  1. 01

    在 GUI 里画路径

    在场地图上拖航点，PathPlanner 画出样条并算出轨迹。

  2. 02

    组成 auto + 加事件标记

    在 GUI 里把多条 path 和 command 拼成一个 .auto，并在该触发动作的地方放事件标记（命名为 ShootNow、StartIntake…）。

  3. 03

    存盘 → deploy/pathplanner/

    .path 和 .auto 文件存进项目的 deploy 目录，随下次 deploy 一起送上 roboRIO。

  4. 04

    AutoBuilder.configure(...) + NamedCommands.registerCommand(...)

    启动期一次性把底盘接进 PathPlannerLib，并注册每条命名命令。GUI 里的事件标记就解析到这些名字。

  5. 05

    构造 auto chooser 或按名加载

    调用 AutoBuilder.buildAutoChooser() 把每个 .auto 显示到 dashboard 上，或用 new PathPlannerAuto("name") 直接加载一个。两种方式都得到一个可运行的 Command。

强项与注意

强项与一个注意点

PathPlanner 赢在速度和迭代。画得快，事件标记不动代码就能把一条路线变成完整得分流程，还支持实时改道。要记住的一点是：它的样条顺滑，但不时间最优。

上手快 点 → 拖 → 完事

上手快，Week 1 的 auto 差不多 20 分钟点点拖拖就成，然后直接送上场。

事件标记 路径即流程

事件标记把路径直接变成完整得分流程，代码不用改 —— 放个标记，注册一次 NamedCommand，搞定。

实时改道 pathfindToPose(...)

支持 pathfindToPose(...) 这种实时改道：从当前 pose 到目标动态生成一条路径。

注意：顺滑非最优 顺滑 ≠ 时间最优

PathPlanner 的样条顺滑，但不时间最优。机器人能跟上，只是未必是约束下最快的那条。当路径本身成为瓶颈时，再看 Choreo。

常见的坑

常见的坑

PathPlanner 上浪费的时间，大半来自三个反复出现的坑。它们都不会报明显的错 —— auto 就是跑得不对。提前知道它们，能在场边省下一个抓狂的下午。

  1. 01

    代码里的 robot config 和 GUI 里的对不上

    AutoBuilder 里 robotConfig 的质量、转动惯量、模块几何，必须和你在 PathPlanner settings.json 里填的一致。对不上时，path follower 会和真实机器人较劲 —— 路径看着没问题，但动作过冲、不到位或来回振荡。

  2. 02

    在加载 auto 之前忘了注册命名命令

    NamedCommands.registerCommand(...) 必须在构造 auto 之前跑完。如果某个 .auto 引用了一个从未注册过的事件标记名，那一步在运行时什么都不做（或报错）。先把每条命名命令注册好，再调 buildAutoChooser() 或 new PathPlannerAuto(...)。

  3. 03

    alliance 翻转行为搞错

    你只画一次路径（通常画在蓝方），alliance 翻转 supplier —— () -> getAlliance().map(a -> a == Alliance.Red) —— 负责为红方镜像。这个布尔值取反了，画得再完美的 auto 也会朝场地另一头开。先在 sim 里确认翻转正确，再上场。
