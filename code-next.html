你站在哪里

你现在拥有什么

你已经有了：用 Subsystem 组织的代码、控制器绑定的 Command、可控的底盘、按键控制的机构、至少一条 auto，以及一套每天都在用的工具肌肉记忆。这就叫“可用”。

技能树

进阶技能树（按 build order）

有了能跑的机器人之后，路会分叉，但有一条主干所有人都走。Closed-loop control 排在最前 —— 它上面的几乎一切，都假设机构能稳在一个 setpoint，而不是只用固定功率傻转。从这里往上爬：辨识你的增益、加上 motion profile、迁移到 swerve 和 odometry、融合 vision，再到进阶 pathing。最后一级根本不是某个工具 —— 而是学会去读那些已经爬上去的队伍的代码。

把它当成一条竖直的攀爬来读。每一级编号大致对应一篇未来的 wiki 文章；括号里的名字，是你爬到那一级时会遇到的库和工具。

  1. 01

    Closed-loop control（PID + Feedforward）

    其他一切都站在它上面的地基。你不再用固定功率开电机，而是下达一个目标 —— 一个 velocity、一个 position、一个角度 —— 让 controller 把误差驱到零。PID 负责 feedback；feedforward 项预测一个已知负载需要多少出力。把它吃透，机构就从“勉强能动”变成可重复地命中 setpoint。它和一段 telemetry 深入（AdvantageKit、DataLog）并行推进，这样你才看得见 loop 真的在收敛。

  2. 02

    SysId —— 辨识你的增益

    靠试错手调 PID 也行，但又慢又像玄学。WPILib 的 SysId 工具会跑一组结构化的动作、记录响应，替你算出物理意义明确的 feedforward 与 feedback 增益。它把“一点点拨 kP 直到不再震荡”变成一次真正的测量。

  3. 03

    Profiled PID 与 Motion Magic

    裸 PID 会用全力猛地扑向目标。Motion profile 给这条路塑形 —— 加速、巡航、减速 —— 让机构平滑、准时地到位。WPILib 给你 ProfiledPIDController；Phoenix 6 把同样的思路直接烤进了电机控制器上的 Motion Magic。这就是“一抖一抖的 elevator”和“顺滑滑上去的 elevator”之间的差距。

  4. 04

    Swerve 底盘（本队当前平台）

    Swerve 让每个轮子都有自己的转向电机和驱动电机，于是底盘可以朝任意方向平移、同时独立旋转。它就是本队今天在用的平台，且依赖它下面的一切：drive 电机上的 closed-loop velocity、steer 电机上的 closed-loop angle，全都调好。Phoenix Tuner X 甚至有一个 Swerve Project Generator 帮你把骨架搭出来。

  5. 05

    Odometry + Pose Estimator

    一旦轮子能精确运动，你就能追踪机器人在场地上的位置。Odometry 把轮子和 gyro 的运动积分成一个实时的 (x, y, heading) pose。Pose Estimator 更进一步，把这套航位推算和外部测量融合起来，让 drift 被修正而不是一直累积。每一条 path-following 和 auto-aim 流程，读的都是它。

  6. 06

    Vision（Limelight、PhotonVision、AprilTags）

    一台能识别 AprilTags 的相机，给机器人一个对场地的绝对定位 —— 一个 Pose Estimator 可以融合进去、抹掉累积 drift 的测量。Limelight 和 PhotonVision 是两套常见的 coprocessor 方案。Vision 让机器人能对准一个它够不着的目标，在场地任意位置完成 score。

  7. 07

    进阶 path planning（Choreo 优化、on-the-fly）

    你最初的 auto 跟的是预先画好的路径。下一级是优化它们 —— Choreo 在你机器人真实约束下解出耗时最短的 trajectory —— 并且 on-the-fly 生成路径，在运行时朝一个移动的、或刚刚检测到的目标现搭一条路线，而不是从固定文件里读。Vision、odometry、pathing 在这里汇到一起。

  8. 08

    读顶尖队的 Open Alliance 代码（254 · 1690 · 6328 · 1678）

    最后一级不是某个库 —— 而是一种习惯。顶尖队伍把整个赛季的代码在 Open Alliance 下公开。每一行都是建立在你已经会的四个核心部件上的 Command-Based 程序，只是把上面每一级都爬完了。读它们，是看清整棵技能树如何在一台真实参赛机器人里拼起来的最快方式。从哪开始读，见下一节。

Open Alliance

读顶尖队的代码

Open Alliance 是一群把整套机器人代码 —— 常常连同 build thread —— 在 GitHub 上公开的 FRC 队伍。对一个过了新手阶段的程序员来说，这是现存最丰富的学习资源，没有之一。下面这几支队伍做这件事已经好几年，他们的仓库被广泛阅读和借鉴。打开任意一个、找到 RobotContainer，你会立刻认出那四个核心部件 —— 然后去看一支冠军级队伍是怎么把它们放大的。

别想着从头到尾通读一整个 repo。挑一个你在意的机构 —— 比如他们的 shooter 或者 swerve module —— 从 subsystem 顺着追到用它的 command，再追到 RobotContainer 里绑定它的地方。这一条线索教给你的，比任何 tutorial 都多。

Open Alliance 254 队 —— The Cheesy Poofs

FRC 史上荣誉最多、被研究最多的队伍之一。他们的代码以干净、有野心著称 —— 是“一套打磨过的 Command-Based 代码能长成什么样”的标杆。

github.com/team254
Open Alliance 1690 队 —— Orbit

一支顶级的国际强队。他们的 swerve、vision 和 auto 是研究一套现代、高性能机器人栈的极好范例。

github.com/Team1690
Open Alliance 6328 队 —— Mechanical Advantage

AdvantageKit 和 AdvantageScope 背后的队伍。读他们的代码，是理解那两套工具所服务的“日志 + 回放”开发风格的最佳途径。

github.com/Mechanical-Advantage
Open Alliance 1678 队 —— Citrus Circuits

长期的 Open Alliance 贡献者，公开的代码和 tech talk 都很扎实。等 254 读熟了，它是一个可靠的“第二个仓库”。

github.com/frc1678

把这些仓库和队伍公开的 tech talk 配着看 —— 尤其 1678 和 6328 会发布深度讲解，带你逐段走过你正在读的那份代码。

常见的坑

过了新手阶段最容易踩的坑

离开基础之后，踩的坑也变了。其中大多数，要么来自用错误的顺序爬这棵技能树，要么来自在下一层还没夯实之前就去够上面那个炫的功能。

  1. 01

    在 closed-loop control 通之前就跳去 swerve 或 vision

    Swerve 就是八个电机上的 closed-loop velocity 和 angle；vision 修正喂给的那个 pose，只有在 odometry 可信时才有意义。跳过地基，你会同时调试一摞叠在一起的层，分不清到底哪一层坏了。请按顺序爬这棵树。

  2. 02

    永远在手调 PID，而不去用 SysId 测一遍

    凭手感拨 kP 能吃掉好几天，最后留下一组没人说得清的增益。SysId 跑一组结构化测试，几分钟就算出物理意义明确的增益。当调参开始像玄学时，别再猜了，去测。

  3. 03

    不上 pose estimator 和 vision 就盲信 odometry

    纯轮式 odometry 会 drift —— 轮子打滑、gyro 漂移，误差只增不减。一场比赛打到后面，机器人对自己位置的判断可能差出一米。融合了 AprilTag vision 的 Pose Estimator 会修正这种 drift，而不是任它堆积。别把 auto-aim 单独建在裸 odometry 上。

  4. 04

    照搬顶尖队的代码却不理解它

    Open Alliance 的仓库是用来学的，不是用来复制粘贴的。254 的某个抽象，是在他们整套架构里才说得通的，未必适合你。读，是为了理解那个模式，然后写出你自己的版本 —— 你调不动的代码，比没有这段代码更糟。

上面技能树的每一级，都计划单独成为一篇 wiki 文章。在它们上线之前，下一节里的官方文档和 Open Alliance 仓库就是你该去的地方。

去哪读更多

上面每一级背后，都有权威的文档。当这份 wiki 还没覆盖某个主题时，下面这些就是第一手来源 —— 各个库的官方文档、FRC 问题被解决的社区论坛，以及那本把这一切底层控制理论讲清楚的书。

官方文档 WPILib · Phoenix 6 · REVLib

三个核心库。WPILib 文档覆盖 PID、feedforward、profile、odometry、pose estimation 和 SysId；Phoenix 6 和 REVLib 记录电机控制器 API 与 Motion Magic 这类板载特性。

docs.wpilib.org · v6.docs.ctr-electronics.com · docs.revrobotics.com
官方文档 PhotonVision · Limelight · PathPlanner · Choreo

vision 与 pathing 方案。PhotonVision 和 Limelight 文档讲 AprilTag pipeline 与 pose 融合；PathPlanner 和 Choreo 文档讲 trajectory 的生成与跟随。

docs.photonvision.org · docs.limelightvision.io · pathplanner.dev · choreo.autos
社区 Chief Delphi 与 Open Alliance

Chief Delphi 是 FRC 的主论坛 —— 提问前先搜，因为几乎每个问题前人都踩过。Open Alliance 的 GitHub 组织（254、1690、6328、1678、3015 等）托管着公开的队伍代码。

chiefdelphi.com · github.com (Open Alliance orgs)
书 Controls Engineering in FRC

Tyler Veness 写的这本免费书，是 closed-loop control、feedforward、motion profile 和 state-space 底下那套控制理论的深度参考。当你想知道增益为什么管用、而不只是怎么设它们时，读它。
